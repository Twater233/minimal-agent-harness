# AI Prompt 与问题解决记录

本项目在 2026-10-19 使用 AI 辅助完成。以下是本次实际协作的任务摘要、关键决策与验证过程，不是虚构的手工开发日志。完整系统提示在 `agent_harness/context.py`，摘要提示也在同文件。

## 任务输入

用户提供笔试要求：从零实现最小 Agent，真实 LLM API，至少三个工具且 todo 必需，支持独立 session、上下文和追问、基础压缩、异常与 trace、测试；提交 GitHub、README、AI Prompt 与问题解决记录，并在五个架构模块各回答一题。随后指定 `gpt6.1sol` 模型和 GitHub 账号 `Twater233`。

## 实际采用的关键提示与约束

| 阶段 | 提示或要求的核心内容 | 形成的决定 |
| --- | --- | --- |
| 需求拆解 | 不使用现成 Agent 框架；明确 session 和 memory 的边界 | Python CLI＋SQLite；同一用户不同 session 不共享待办 |

## 问题与解决

1. **本机没有 gh 命令。** 检查 Git Credential Manager，确认现有 GitHub 登录是 Twater233。通过 GitHub REST API 创建仓库并使用 git 推送，无需安装额外 CLI；凭据仅在进程内使用，不打印、不写仓库。
2. **最初没有模型凭据。** 不读取 Codex 内部认证，不把当前聊天当成项目的真实 API 调用。提供 `.env.example` 和可独立执行的 live 验收，明确离线测试不能替代真实调用。模型 ID 通过官方模型页核对为 `gpt-6.1-sol`，未擅自换模型。
3. **工具消息配对可能被压缩破坏。** 按用户回合切分历史，压缩完整旧回合，当前回合不切块。测试保留 assistant/tool 的 call ID 对应关系。
4. **待办状态不能靠摘要判断。** 每次决策从 SQLite 查询当前 session 的 todos；摘要只保留对话背景。测试重启进程后的状态和不同用户/窗口隔离。
5. **日志 INSERT 占位符错误。** 第一轮 23 项测试中 11 项因 `7 values for 6 columns` 中断，修正为六个占位符后原 23 项全部通过。后续增加传输层与边界测试，最终数量见验证记录。
6. **进程可能在副作用发生后、结果落盘前中断。** 恢复时补 Interrupted 结果，不自动重放；明确要求先查当前状态。这个方案避免盲目重试，但不虚称 exactly-once。
7. **摘要服务本身可能失败。** 捕获模型/协议错误，退化为有长度上限的片段，明确旧细节可能丢失。禁止把片段当作完整可靠记忆。
8. **公开协议与产品实现容易混淆。** 架构题区分 Anthropic/OpenAI-compatible 协议与 Claude Code harness；不能验证的产品内部行为不写成结论。

## 可以自行复核的点

阅读 `runtime.py` 可追踪完整循环；阅读 `tools.py` 可确认 Schema 与实际执行都由本项目负责。运行测试能看到错误恢复、隔离、压缩、中断和限制是否成立。真实模型是否按预期选择工具，必须用自己的 API 配置跑 `scripts/live_smoke.py`，再查看 `.agent/live-smoke.json`，不能由这份协作记录替代。
